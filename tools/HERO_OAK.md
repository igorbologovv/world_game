# Hero Oak — original procedural 3D tree for world_game / Bevy 0.14

A large, organic oak with tapered, curved trunk and branches, visible roots,
procedural bark, double-sided leaf-card foliage with RGBA cutout, and four LODs.
All textures and geometry are generated by the script; no external assets.

## Files

| Asset | Geometry | Suggested distance |
|---|---:|---|
| `oak_lod0.glb` | 33,524 triangles | 0–50 m, heroic close-up |
| `oak_lod1.glb` | 4,384 triangles | 50–100 m |
| `oak_lod2.glb` | 626 triangles | 100–170 m |
| `oak_lod3.glb` | 8 triangles | 170+ m (two double-sided cross cards) |

GLB files contain embedded color and alpha textures. They are **Y-up**
(gltf convention) and roughly 22 metres tall; the root is at the origin.

## Generate or edit in Blender (Blender 4.x)

```bash
# Arch Linux
sudo pacman -S blender

# Generate GLB and editable hero_oak.blend with selectable LOD models
blender -b --python build_hero_oak.py -- --output ./hero_oak
```

In Blender UI you can also switch to **Scripting** and run the contents of
`build_hero_oak.py` (adjust `--output` appropriately). The four models are
separate Blender meshes. LOD0 stays visible; other LODs are hidden.

Standalone generator (without Blender, requires `trimesh` and `Pillow`):

```bash
python build_hero_oak.py --output ./hero_oak
```

This creates all GLBs and texture PNGs, **not** a `.blend` file. A separate
preview PNG was generated by a local 3D viewer for inspection.

Different deterministic variants:

```bash
blender -b --python build_hero_oak.py -- --output ./oak_variant_2 --seed 18203
```

## Import into `world_game` (Codex handoff)

1. Copy all four `.glb` files into
   `~/world-client/assets/models/hero_oak/`.
2. Load the scenes using Bevy 0.14's `AssetServer`:

```rust
let oak_models: [Handle<Scene>; 4] = [0, 1, 2, 3].map(|lod| {
    asset_server.load(format!("models/hero_oak/oak_lod{lod}.glb#Scene0"))
});
```

3. Use a Bevy `SceneBundle` containing the selected `Handle<Scene>` as a
   **child** of a floating-origin spatial root. With `bevy_terrain` high
   precision, first calculate a planet-local position (`terrain_aligned_direction`
   + `RADIUS + height`), then obtain `(GridCell, Vec3)` via
   `frame.translation_to_grid(world_position)` and place the root in the frame.
4. Rotate the root from `Vec3::Y` to the sphere's local surface normal:

```rust
let rotation = Quat::from_rotation_arc(
    Vec3::Y,
    world_position.normalize().as_vec3(),
);
```

5. Cache each LOD `Handle<Scene>` once (not per tree). Use deterministic seeds
   for position, yaw and scale; do **not** respawn scenes every frame.
6. Implement distance LOD swaps on a reasonable interval, ideally with 10–15%
   hysteresis. Don't render all 4 LODs of the same tree simultaneously.
7. For hundreds of trees: Bevy `SceneBundle` per tree is a starting point only;
   consider mesh/material instancing or merge distant tree batches by tile.

**Codex task:** Integrate these four GLB scene handles as a `HeroOak` species
in `src/forest.rs`. Preserve spherical alignment, seed consistency, patch
streaming, camera culling, and shadow budget. Test all LODs in POV and in map
view. Check transparent foliage in Bevy. Optimize instances before increasing
plant density. Do not rewrite the terrain shader.

## Notes

- Each file is an **original** tree model generated locally, not a purchased
  asset or copy of someone else's game art.
- Blender back-end was authored but **not executed** in this environment;
  the prebuilt GLBs were exported with the standalone fallback and reloaded
  and rendered with a separate 3D viewer.
- Preview lighting is illustrative, not a test of Bevy's PBR renderer.
- No wind animation or collision mesh yet; those belong in the game integration.
